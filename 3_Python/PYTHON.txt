  -> Recursion - function calls itself

	=> Indirect Recursion or Mutual Recursion - consider 2 function, calling func1 in func2 and calling func2 in func1 recursively.

	[USA]
		def even(n):
			if n == 0":
				return True
			return odd(n - 1)

		def odd(n):
			if n == 0:
				return False
			return even(n - 1)

		print(even(10))
		print(odd(7))
	
	=> Tail Recursion - function calls itself at the last live of the function.
		[Note: python didn't do optimized tail recursion as it have heap, but not stack]

	[USA]
		def show(n):
			if n == 0:
				return
			print(n)
			show(n - 1)
		show(5)

	=> Head Recursion - function calls happens directly after the base condition.

	[USA]
		def show(n):
			if n == 0:
				return
			show(n - 1)
			print(n)
		show(5)

	=> Tree Recursion - similar to BST, Bactracking (the <function> that calls itself with n child <function>)
	
	[USA]
		def fib(num):
			if num <= 1:
				return num
			return fib(num - 1) + fib(num - 2)
		print(fib(5))

	=> Nested Recursion

		-> A recursive function where the recursive call is passed as an argument to another recursive call.

		[WHY]

			Used when the next recursive call depends on the result of another recursive call.
Common in theoretical recursion problems.

		[SYN]

			def func(n):
    				if base_condition:
        				return value
    				return func(func(n - 1))

		[USA]

			def nested(n):
    				if n > 100:
        				return n - 10
    				return nested(nested(n + 11))

			print(nested(95))

		[RES]

			91

		[EXA]

			McCarthy 91 Function


	=> Linear Recursion

		-> Each function call makes exactly one recursive call.

		[WHY]

			Simplest form of recursion.
			Used for traversing numbers, strings, linked lists, etc.


		[SYN]

			def func(n):
    				if base_condition:
        				return
    			func(n - 1)

		[USA]

			def show(n):
    				if n == 0:
        				return
    				print(n)
    			show(n - 1)

			show(5)

		[RES]

			5
			4
			3
			2
			1

		[ANE]

			def factorial(n):
    				if n == 0:
        				return 1
    				return n * factorial(n - 1)

			print(factorial(5))

		[RES]

			120
	=> Binary Recursion

		-> Every recursive call creates 2 recursive calls.

		[WHY]

			Used for divide-and-conquer algorithms.
			Common in Fibonacci, Binary Trees, Backtracking.


		[SYN]

			def func(n):
    				if base_condition:
        				return
    			func(n - 1)
    			func(n - 2)

		[USA]

			def fib(n):
    				if n <= 1:
        				return n
    				return fib(n - 1) + fib(n - 2)

			print(fib(5))

		[RES]

			5

		[EXA]

			Fibonacci
			Binary Tree Traversal

		[CAT]

			Slower because many repeated recursive calls are made.
	
	=> N Array Recursion (N-ary Recursion)

		-> Every recursive call creates N recursive calls, where N can be any number greater than 2.

		[WHY]

			Used when one state can generate multiple next states.
			Common in graph traversal, game trees, combinations, permutations.

		[PAR]

			Depends on the branching factor.

		[SYN]

			def func(node):
    				for child in children:
        				func(child)

		[USA]

			graph = {
    				'A': ['B', 'C', 'D'],
    				'B': [],
    				'C': [],
    				'D': []
			}

			def dfs(node):
    				print(node)
    				for child in graph[node]:
        				dfs(child)

			dfs('A')

		[RES]

			A
			B
			C
			D

		[ANE]

			def print_paths(level):
    				if level == 0:
        				return

    				for _ in range(3):      # 3 recursive calls
        				print_paths(level - 1)

			print_paths(2)

		[EXA]

			DFS on N-ary Trees
			Graph Traversal
			Game Search
			Backtracking with multiple choices

		[CAT]

			Can become expensive because the number of recursive calls grows rapidly.

	-> SOLID PRINCIPLES - Five design principles used in Object-Oriented Programming to create maintainable, flexible, and scalable software.

	[USC]
		- scalable
		- easy evaluation
	[TYS]

	1. S -> Single Responsibility Principle (SRP)
		- A class should have only one reason to change.
		- One class = one responsibility.

	2. O -> Open/Closed Principle (OCP)
		- Software entities should be open for extension but closed for modification.
		- Add new behavior without changing existing code.

	3. L -> Liskov Substitution Principle (LSP)
		- Child classes should be replaceable with their parent classes without breaking the program.
		- Subclass must behave like its superclass.

	4. I -> Interface Segregation Principle (ISP)
		- A class should not be forced to implement methods it does not use.
		- Prefer small, specific interfaces.

	5. D -> Dependency Inversion Principle (DIP)
		- High-level modules should depend on abstractions, not concrete implementations.
		- High-level classes should not depend directly on to the low level classes.
		- Depend on interfaces, not details.

	GIL (Global Interpreter Lock)
		- a lock in CPython that allows only one thread to execute Python bytecode at a time
		- prevents multiple threads from modifying Python objects simultaneously and avoids memory conflicts
		- threads can run concurrently (switching between tasks), but CPU-bound Python code does not get true parallel execution on multiple CPU cores

		[WHY]
			- Memory Management
			- Reference

	Multiprocessing (Python)
    - runs multiple processes independently to achieve parallel execution
    - bypasses Python GIL and uses multiple CPU cores

	[Process]
		- creates a new independent process
		- used to run a function in parallel

	[Pool]
		- creates a group of worker processes
		- automatically distributes tasks among workers

		[USA]
			from multiprocessing import Pool

			def square(num): 
				return num * num
			
			if __name__ == "__main__":
				nums = [1, 2, 3, 4, 5]
				with Pool(processes=2) as pool:
					result = pool.map(square, nums)
				print(result)

	[Queue]
		- allows safe data sharing between processes
		- follows FIFO (First In First Out) communication

		[USA]
			from multiprocessing import Process, Queue

			def worker(q):
				for i in range(1, 6):
					q.put(i)
			
			if __name__ == "__main__":
				q = Queue()

				p = Process(target=worker, args=(q,))
				p.start()
				p.join()

				while not q.empty():
					print(q.get())

	[Pipe]
		- creates a communication channel between two processes
		- used for direct sending and receiving data

	[Lock]
		- allows only one process to access shared data at a time
		- prevents race conditions

	[Semaphore]
		- controls how many processes can access a resource simultaneously
		- useful for limiting resource usage

	[Event]
		- sends a signal between processes
		- used to notify a process that something happened

	[Condition]
		- allows processes to wait until a specific condition is met
		- used for advanced process synchronization

	[Value]
		- creates a shared single variable between processes
		- used for sharing numbers or simple data

	[Array]
		- creates a shared memory array between processes
		- used for sharing multiple values

	[Manager]
		- provides shared objects between processes
		- supports shared list, dictionary, and other data structures

	CPU Bound
	
	- Heavy calculations (CPU does most of the work)
	- Uses CPU continuously instead of waiting
	- Performance depends on CPU speed
	- Uses multiple CPU cores for better performance
	- In Python, Multithreading does not improve CPU-bound tasks because of GIL
	- Best solution is Multiprocessing (separate processes)
	

	[WHY]
	- To perform heavy calculations faster
	- To use multiple CPU cores
	- To avoid GIL limitation
	- To improve execution speed of CPU-intensive programs
